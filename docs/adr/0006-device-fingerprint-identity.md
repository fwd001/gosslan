# ADR-0006: 设备指纹作为唯一身份（无账号体系）

## 状态

已采纳（v0.1.0，前缀改 `gosslan-` 于 v0.8.0）

## 背景

Gosslan 定位为"无服务器、无注册"的局域网即时通讯。需要一种方式唯一标识设备/用户，且不依赖任何中央服务。

## 决策

使用**设备指纹**（`device_id`）作为唯一身份标识：
- 前缀 `gosslan-`（v0.8.0 起，原为 `dev-`）
- 桌面端：基于 `machine-uid` crate 获取系统级唯一 ID
- 移动端：UUID 生成 + 持久化本地 SQLite（重启不变）
- 身份密钥对（X25519 + Ed25519）与 device_id 绑定，私钥存本地 SQLite

**无账号、无登录、无注册**。连上局域网即自动 announce 身份。

## 考虑过的方案

1. **用户名+密码**：需要服务器验证 → 与"无服务器"定位矛盾 → 放弃
2. **纯随机 UUID（每次安装新生成）**：重装 = 身份丢失 = 好友全断 → 放弃
3. **machine-uid + 持久化密钥**：硬件绑定 + 本地存储，重装应用（不重装系统）身份不变 → 采纳
4. **去中心化 DID**：过度设计，局域网场景不需要全球唯一 → 放弃

## 代价

- **设备重装系统 = 身份丢失**：好友需要重新添加（公钥变化）
- **多设备同步困难**：一个 device_id = 一个设备，无法多端登录（远期计划通过账号绑定解决）
- **machine-uid 仅桌面**：Android 需要兜底方案（UUID 持久化）
- **v0.8.0 前缀变更是破坏性的**：升级后 device_id 变化，需重新添加好友

## 推翻条件

当引入"账号体系"时（路线图远期），device_id 之上叠加账号绑定，实现多设备同步。但 device_id 作为设备级标识仍然保留，账号是可选的上层抽象。
