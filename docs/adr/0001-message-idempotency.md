# ADR-0001: 消息幂等性与确定性 msg_id

## 状态

已采纳（v0.4.1）

## 背景

Gosslan 的消息可以通过三条路径到达接收方：直发（TCP ChatMessage）、Gossip 广播、Outbox 离线补发。在 v0.4.1 之前，Gossip 落库的 msg_id 带 `g-` 前缀，而 outbox 补发使用 UUID，两者不同导致极端竞态下出现重复消息。

## 决策

所有路径共用 Gossip 信封的**确定性 SHA-256 message_id**（= SHA-256(sender_id + ts + payload)）。接收方通过 `message_exists(msg_id)` 做幂等去重：收到重复 msg_id 只回 Ack，不重复入库。

## 考虑过的方案

1. **UUID v4 随机生成**：每条路径各自生成 → 跨路径无法去重 → 放弃
2. **发送方生成 UUID 并全路径携带**：可行但 Gossip 信封已有 SHA-256 机制 → 无需额外 UUID
3. **接收方按内容去重（hash body）**：相同内容的合法消息会被误杀 → 放弃

## 代价

- msg_id 依赖发送方时钟：如果同一毫秒发送两条完全相同的消息，理论上会冲突（实际极不可能）
- 消息内容或时间戳变化会产生不同 msg_id（重发 = 新消息，这是正确行为）

## 推翻条件

如果未来引入消息编辑/撤回功能，需要 msg_id 与内容解耦（编辑不应改变 ID），此时需要重新设计 ID 生成策略。
