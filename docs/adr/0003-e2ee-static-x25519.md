# ADR-0003: E2EE 采用静态 X25519 而非 Noise XX

## 状态

已采纳（v0.2.0），计划演进（Noise XX 为 P0 路线图）

## 背景

Gosslan 需要端到端加密保护局域网消息隐私。理想方案是 Noise XX 协议（双向认证 + 前向保密），但项目初期需要快速建立可用的加密通道。

## 决策

当前采用**静态 X25519 ECDH** 派生长期共享密钥 + ChaCha20-Poly1305 AEAD 加密：
- 发送方：`shared = X25519(自己私钥, 对方公钥)` → seal/open
- 群聊：随机群密钥对称加密，密钥用各成员公钥 ECDH 单独封装分发
- Gossip 信封：Ed25519 签名防伪造

v0.11.0 起 E2EE **恒开且不可关闭**。

## 考虑过的方案

1. **Noise XX（snow crate）**：前向保密、双向认证，但需要建链握手状态机、会话管理、密钥轮换 → 复杂度高，延后实施
2. **Signal Protocol（libsignal）**：完整的双棘轮，但引入大型 C 依赖、Android 交叉编译困难 → 放弃
3. **TLS 双向认证**：需要 CA、证书管理，P2P 场景不适合 → 放弃
4. **不加密（局域网可信）**：v0.8.0 曾默认关闭，但中继节点/Gossip 泛洪场景下明文不可接受 → v0.11.0 改为恒开

## 代价

- **无前向保密**：私钥泄露 = 历史消息全部可解密
- **公钥分发依赖**：首次通信前必须获取对方公钥（通过 announce/FriendAccept/who_has 探测）
- **公钥变化窗口**：对方重装应用后公钥变化，期间消息显示为系统提示（不丢失但不可读）

## 推翻条件

当 Protocol v1 稳定 + 测试体系完善后，升级为 Noise XX 会话（TCP 通道先行，蓝牙复用）。
升级时必须保持 v1 兼容期（双版本并行解密）。

## 演进路径

```
当前 v1: 静态 X25519 → ChaCha20-Poly1305
目标 v2: Noise XX 握手 → 会话密钥 → 消息加密（前向保密）
兼容: v2 节点收到 v1 消息仍可解密（enc1: 前缀识别）
```
