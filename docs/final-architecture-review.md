## 三、11 问，逐条给结论（四态：必须改 / 建议改 / 观察 / 不要改）

1. **当前架构是否仍合理？** —— **合理**。分层 UI→api 门面→commands→领域→持久化/网络 仍可核对，`check-domain-deps.mjs` 管着方向。
2. **哪些已经成熟？** —— 协议与不变量（INV 全绑定，条数看 `docs/protocol-invariants.md` 自己被钉的那处）、跨进程 E2E 族（**轮次清单与每轮条数只写在验收矩阵顶部那处"轮次账"**，由判据 C 从 harness 现算对账；每轮都配"只翻判据输入"的反向模式）、护栏非空转层（条数由 `verify-guards.py --list` 自己打印）、迁移台账、跨版本降级（INV-P24）、**运行时键盘/焦点这一层现在有仓内可重跑入口**（`scripts/check-ui-runtime.mjs`）。⚠️ 本条原来写死"15 个 E2E 轮"—— 当天就漂成 16 ⇒ 总数型声明一律不落笔。
3. **结构性技术债在哪？** —— ① 三个 >3000 行的 Rust 文件里"实现与测试交替"（上表）；② `useChatStore` 是全应用状态中心（§23 的锁只保住了"任务计数"这一维）；③ UI 层可测性仍为零依赖纯函数 + 形状判据，没有 DOM 地基（**这是选择，不是缺陷**，代价见第 9 问）。
4. **重复实现？** —— 本轮抓到并消掉一处真的：**收藏自己长了一层整屏图片查看器**（`FavoritePanel.vue` 的 `viewer` + `fixed inset-0` 覆盖层），统一预览能力早已存在（`useImagePreviewStore.openGallery`）。修于 `a077850`，并补了一条**按形状**抓"第二个预览实例"的判据 —— 原来那条只认 `<ImageLightbox>` 标签与名字带 `lightbox` 的 ref，`viewer` 从缝里过去（判据在而抓不到＝半空转，比没有更坏）。
5. **隐性状态？** —— 两处已登记：① "与我相关任务数"依赖 store 里那份 `openTodoByConv` 刷新时机（窗口重新可见/切群/重启都要重拉，已由 `windowEntries.test.ts` 那条通用规则兜住）；② @我 判定**没有 id 可用**（见第 8 问）。
6. **最容易再产生 bug 的地方？** —— ① 任何"同一个数/同一份状态在两处各算一次"（本仓已发生 3 次：未读数、任务弹窗标题 (9) vs 进去 6 条、预览开关）；② 形状类守卫的**锚点漂移**（守卫变强后旧坏法写不出来 → 注入腿白跑一小时）；③ 跨窗口/跨文档的数据投递与让位。
7. **哪些巨型文件值得拆？** —— **只有 `lib.rs` 值得**，且只值得拆一刀：把 `mod tests` 那 ~3.9k 行源码形状守卫搬进独立分册（纯搬家、零语义变化、`include!` 已是现成机制）。拆之前必须先解决第 6 问②：锚点核对已改为**起跑前**做（`794e9ff`），否则搬家会让一批锚点同时失效而没人及时知道。
8. **哪些不值得拆？** —— `transport.rs` 与 `file.rs`：它们的风险集中在状态机时序（link budget、分片收尾、gossip 时序），已被大量行为测试与跨进程轮钉住；搬动会改变 `include!`/私有可见性而**收益只有行数**。`useChatStore` 同论——第一阶段已判"纯搬家、短期只降稳定"，本轮不翻案。
9. **哪些现在不应该动？** —— 见下面第五节那张"已有锁"清单；另加两条：**不给契约图的取数戳加相等判据**（加了等于每次加命令都强迫改文档，与总指令§十四顶；本轮改为把口径写进那一行本身），以及**不引入 DOM 测试地基**（本轮用零依赖的 CDP 探针就验到了运行时键盘，不需要为它加 jsdom/vitest）。
10. **哪些进下一版？** —— §10 的结构化 @ 目标（协议字段，需拍板）、§28 缺的"断一条链路/断所有链路/建群中退出"那一族轮次、§36 Windows 内置 WebView2 打包、§91 按窗口 id 截图（证明"界面真的在截图里"）。⚠️ 本条原来还列着 **§22 任务专项 E2E 轮**与 **§29 任务生命周期可观测性** —— 两项已于 2026-09-27 当天落地（前者：`--round=task`，含发起方换向 / 重启不退 / 发送端崩溃 / 图片引用过线；后者：命令层 + 内核自 emit 两处关键节点日志 + Rust 守卫钉"顺序 + 标记 + 隐私"），从这一条里移出。
11. **哪些应永远保持现状？** —— 「不新增功能、只把已存在的功能做完整」这条产品姿态；「SQLite 不存 BLOB、图片按引用异步取字节」；「同机多实例经 LAN 必互达 ⇒ 不再造'两者无链路'型判据」；「版本号五处同步 + CHANGELOG 落小节」。
