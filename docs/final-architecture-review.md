"把所有能自动测的功能都划进自动测试"这句话要能复查，先得有一张"哪些后端能力从没在任何判据语料里出现"的清单。
**不在这里抄一份数字**（抄了就成第二份事实源，当天就漂），只写口径：

```
npm run coverage:features          # 汇总：分母 + 直接命中 + 经委托命中 + 三样都不沾
npm run coverage:features -- --all # 逐条列出（含"经委托"是委托到哪个 db 函数，便于抽查）
```

分母是 `src/api/index.ts` 里出现的每一个后端名字（invoke 的命令名 + listen 的事件名），现算。
语料只算"测试/守卫/E2E"这一侧（生产码不算，否则每个名字都命中自己）。三态的含义与边界：

| 态 | 含义 | 要防的误读 |
|---|---|---|
| 直接命中 | 名字出现在某份判据语料里 | **是线索不是证明** —— 可能只是测试顺手写了这个字符串 |
| 经委托命中 | 命令体是 `db::xxx(...)` 的薄包装，而 `xxx` 出现在语料里 | 只说明被委托的函数被测过，不保证这条命令的语义被断过 |
| 三样都不沾 | 两处都搜不到 | 里面**大部分是 OS/窗口 pass-through**（最小化、全屏、打开下载目录、剪贴板…），那类本来就该记 MANUAL 而不是编个假测试 |

4 条行为断言（只回两种 kind / **任务行本身过百也不许被截断** / seq 递增且带回 @ 落点列 / 多会话不串）。
