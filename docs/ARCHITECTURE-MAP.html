129 条 输入 → 输出 规则，按后端定义处（src-tauri/src/commands/<模块>.rs）分组。输入/输出两列是从 Rust 函数签名直接抽的（str=String、int=i64/u32、X?=Option、X[]=Vec、|err=Result 的错误分支），语义列是判"是否符合需求"的地方。 前端另有 33 个事件把状态推回去，见"事件契约"。

后端 → 前端的唯一反向通道：29 个事件名，同类合并成 28 行。这张表是判"某个状态变化界面看不看得到"的清单：一条状态改动如果没有对应事件，常驻窗口就永远停在旧快照（这类退化本仓库真踩过：设置窗口改语言/主题后主窗不刷新）。

事件载荷谁发 / 何时谁收（消费者）范围

SQLite 只存文本、密钥、关系与队列；二进制一律落盘（storage/mod.rs 的硬原则）。全库 19 张表：零 CHECK、零 FOREIGN KEY，状态枚举与级联删除全靠应用层 SQL 自己守 —— 所以下面"状态取值"和"谁写"两列就是真正的契约。
