# 大规模局域网性能设计（500–1000 节点）

本文档说明 Gosslan 在 500–1000 节点规模下的性能策略、已做的优化点，以及在不同网络规模下的预期表现。

## 1. 目标与瓶颈模型

目标是 **500–1000 台设备在同一局域网内稳定在线、正常收发消息、UI 流畅**。

在纯 P2P + Gossip 架构下，节点数 N 增大时，主要瓶颈不是单条消息的延迟，而是：

1. **UDP 发现风暴**：每个节点周期广播 `announce`，N 越大，每个节点每秒收到的广播包越多（O(N)），处理与展示成本线性上升。
2. **节点表 IPC 推送**：每次广播都全量序列化 N 个节点并推给前端，N=1000 时每秒数百次全量推送会拖垮 Tauri IPC。
3. **冗余写库**：每条 `announce` 若都写 SQLite（好友公钥更新、群密钥遍历），形成热点。
4. **消息去重容量**：Gossip 去重结构容量不足时，误判/漏判导致消息丢失或风暴。
5. **前端渲染**：密集广播下一次性挂载上千行 DOM 会卡顿主线程。

## 2. 已做的优化

### 2.1 节点表事件节流合并（关键）
- `state.rs`：`emit_peers()` 不再立即全量序列化推送，而是「置脏 + 通知」。
- 由 `spawn_peer_emitter` 在 **约 300ms 合并窗口**内最多推送一次节点表。
- 效果：无论每秒收到多少条广播，前端节点列表更新被压到 **≤ ~3 次/秒**。

### 2.2 自适应广播周期 + 抖动
- `discovery.rs`：广播周期随在线节点数自适应——<100 节点 5s、≥100 节点 10s、≥500 节点 20s。
- 每次广播叠加 0–2s 随机抖动，打散各节点广播相位，避免「整网同时齐发」的惊群效应。
- 效果：N=1000 时单节点广播由 12 次/分降到 3 次/分，全网 UDP 流量显著下降。

### 2.3 消除每条 announce 的冗余写库
- `transport.rs::upsert_peer`：仅在「新节点」或「公钥首次学到/变化」时才写好友公钥、遍历群组补发群密钥。
- 效果：稳态下（所有节点公钥已就绪）每条心跳不再触发任何 SQLite 写操作。

### 2.4 SQLite 调优
- 建表脚本补全 `friends` 表 `x25519_pubkey / ed25519_pubkey` 列（修复运行时报错）。
- `journal_mode=WAL` + `synchronous=NORMAL`：提升高频落库吞吐，代价是极小概率的崩溃一致性损失。
- 消息表 `msg_id` 唯一约束（去重）+ `(conv_id, ts)` 索引（分页查询）。

### 2.5 Gossip 去重与扇出
- Bloom Filter（容量 10 万，误判率 1%）+ LRU 精确去重（容量 1 万）双级去重，防止环路与网络风暴。
- 固定 fanout=4、TTL=6：4 叉随机图的直径约 `log₄(N)≈5`，TTL=6 足以覆盖 1000 节点；中继节点仅透传密文。
- `handle_gossip` 将「去重 + 验签」合并为一次锁，减少高负载下锁竞争。

### 2.6 前端渲染
- 消息列表虚拟滚动（`VirtualList.vue`）+ 主线程同步合并（O(n) Set 去重 + 排序，微秒级）+ rAF 批处理入队（`useChatStore.ts`，窗口不可见时退回 setTimeout）。
- **刻意不用 Web Worker**：WKWebView 生产构建下 Worker 可能加载失败导致消息管线 Promise 永不 resolve（v0.5.1 教训，详见 `docs/adr/0005-no-web-worker.md`）。
- 添加好友弹窗：搜索过滤 + 最多渲染 200 行 + 数量提示，避免一次性挂载上千行。

## 3. 规模预期

| 规模 | 广播周期 | 单节点接收速率 | 预期表现 |
| --- | --- | --- | --- |
| ≤ 100 节点 | 5s | 低 | 无压力，秒级发现 |
| 100–500 节点 | 10s | 中 | 流畅，无需特殊处理 |
| 500–1000 节点 | 20s | 高 | 依赖节流 + 自适应广播，正常收发流畅；文件/大消息走切片中继 |

## 4. 尚未做 / 可扩展

- **QUIC 替代 TCP**：多路复用、连接迁移，进一步降低高并发连接数开销（架构已预留 `Message` JSON 线格式，便于切换）。
- **部分 Mesh / 邻居子集**：当前是「小 ID 主动拨号」的全连接策略，N=1000 时单节点约 1000 条 TCP 连接；可改为只连 O(log N) 个邻居 + 多跳转发。
- **中继服务器**：跨网段 / 电脑↔移动端的中转（README 已有路线图），可用 WebSocket 复用同一套 `Message` 协议。
