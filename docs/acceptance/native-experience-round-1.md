## 9. 回滚方法和下一轮优先任务

回滚：本轮改动按"一个根因一个提交"切的，且**未推送 33 条**（现算 `git rev-list --count origin/main..HEAD`），
所以回滚粒度是单个提交（`git revert <sha>`）而不是整批。量具与文档（`perf/`、roadmap、design-guidelines）
不动产品行为，可独立回滚。护栏类改动回滚时要**同批**撤掉 `designGuards.ts` 与 `guard_cases/` 里对应那条，
否则会出现"守卫钉着已经撤掉的写法"。

下一轮优先（按 §十 的 P0>P1>P2>P3，且都在我这边可执行）：

1. **先把未推送区间推上去、让 CI 判一次**（负责人动作）——本地跑绿不等于 CI 那轮绿。
2. **N27 真机那半 / N18**：一次性把真机验收那 5–7 条做完并把结论写回矩阵（人工验收，不升格）。
3. **N23**：堆快照解析那一条（有明确方法，只差实现成本，属可控）。
4. **判据 3 的处置**：要么按它的建议拆分支，要么由负责人明确"接受这条红挂着"。
5. `verify:e2e` 在解锁屏窗口下补跑一次，消掉那条环境性红。
