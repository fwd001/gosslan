# 当前目标

Gosslan v1.0：**去中心化 mesh 聊天与团队协作工具**，局域网为主、跨网段靠节点互相中继、
蓝牙近场加入。没有服务器、没有账号、没有强制升级通道。

对用户只要求一件事：**像普通 IM 一样无感使用**。

四条验收维度，按此顺序取舍：稳定 → 速度 → 可达 → 安全；外加一条横切要求：
**任何异常都必须可解释**（用户看得懂现在在发生什么，而不是一句"失败"或一个转圈）。

# P0 地基（LAN Chat 本体，必须全绿）

1. 局域网发现（广播/监听/多网卡/虚拟网卡不误判）
2. 好友请求 / 接受 / 删除 / 重新添加（两端状态最终一致，不出现单边好友）
3. 在线 / 离线状态（断链不等于删节点）
4. 双向文本消息、消息去重（msg_id 幂等）
5. Outbox → Ack；Ack 只代表对端已持久化
6. 离线持久化与自动重发（对端离线 ≠ 2 分钟后失败）
7. 网络恢复后不丢不重
8. 已读回执与送达状态（`delivered` = 对方收完，`read` = 对方看到）
9. 失败状态可见且可重试（重发必须重新加密，不得把明文塞进队列）
10. E2EE（身份锚定 friends 表；未验签不得建立信任）
11. SQLite 持久化 + 重启恢复（含在途队列）
12. 图片 / 文件消息（多选并发下不得概率性丢件）
13. 通知（尊重开关，失败要能观察）
14. Windows / macOS / Android 三端构建与基本稳定
15. **两台以上真实设备联调**

# P0 新增（mesh 本体，同样属于 v1.0）

16. 多路径并存与选路：LAN / 跨网段 Routed / 蓝牙；一条有序字节流**必须钉在单条链路**上
17. 中继转发 + 中继授权：设置"关闭/仅好友/白名单"必须真的管到数据面（文件、外部帧）
18. 群聊与团队协作：群消息、群文件、群任务、@提及
19. 删除一致性：删会话/退群/删群不留幽灵数据（在途队列、已读水位、搜索孤儿）
20. 蓝牙近场加入：载荷预算两侧同口径、大帧不得静默丢弃
21. **跨版本优雅降级（INV-P24）**：
    * 收到不认识的帧类型 ⇒ 忽略 + 节流日志，**链路保持**（今天会拆链，属于必修）
    * 渲染不了的内容 ⇒ 「不支持的消息类型，升级后可查看」，**绝不显示裸 JSON**
    * 对端版本更高 ⇒ 界面给可解释状态；对端低于最低支持 ⇒ 明确拒绝并说明"谁需要升级"
    * 新帧 / 新语义 ⇒ 必须先按对端 `protocol_version` / capability 门控（ADR-0007）
22. 性能不互相饿死：大文件传输进行时，聊天与控制帧必须及时送达（三级通道 + 保序）

# 禁止事项（任何一条都算未达标）

* 不要因为 TCP write 成功就认为消息已送达
* 不要绕过 outbox、msg_id 幂等、Ack 中的任何一环
* 不要静默吞掉加密/解密/落盘错误（包括 `.ok()` 与 `let _ =` 把可观察失败吃掉）
* 不要让网络临时失败变成永久失败
* 不要让"界面显示成功"和"对端实际收到"不一致 —— 出现 0% 却已读、100% 却失败，都算缺陷
* 不要为了一个 bug 造第二套逻辑；不要绕过既有单一事实来源（分类表、常量、判据函数）
* 不要新增"未来特性"来证明架构可扩展（范围见 `AI_RULES.md` §3）

# 每个 bug 的固定流程

1. 找到真实数据流（不要按表面现象改）
2. 找到实际断点，写 Root Cause Analysis
3. 判断根因，做**最小**修复（改不动就报告，别自己扩大方案）
4. 加回归测试（钉住机制，不是钉住当前行为）
5. 跑测试，**不得为了让测试通过而改测试预期**
6. 一次修复一个 commit + 一次 patch 版本（SemVer）

`cargo clippy --features bluetooth`。涉及网络/协议/消息链路时另加

改了 wire 帧、消息 kind、DB schema ⇒ 额外确认 INV-P24 与 ADR-0007 的检查项，
并跑一次跨版本自测（新旧两个安装包互发）。

# 报告要求

不要说"理论上应该可以"。必须给：

* 改了什么（文件:行号）、根因是什么
* 做了哪些验证、**哪些真的通过**
* 哪些验证无法执行以及原因（例如需要双真机、需要 GUI）
* commit hash、是否已 push 到 main

真机验收由用户执行；AI 负责给出**可观测判据**（看哪个界面、抓哪个日志前缀、期望看到什么），
并列出"还没在真机上验过"的项，不把源码推断说成实测结论。
